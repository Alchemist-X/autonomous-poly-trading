> 目标：让生成文本接近 The Information / 顶级分析型 newsletter（Levine、Stratechery）——凝练、每句带硬信息、强观点但**概率校准**、零 ChatGPT 腔。

## 1. 三类文本不是一回事（地基）

之前（包括我上一轮）有个不准确的说法：「报告散文只给人看、不进交易」。**已核代码更正**：

| 文本面 | 位置 | 是否影响真钱 | 改风格的风险 |
| --- | --- | --- | --- |
| **A. full-pulse 报告**（LLM 生成的 Markdown） | `full-pulse.ts:832` 生成 → `pulse-entry-planner.ts:496/522` 解析 | **是（trade-bearing）**。报告里的 `\| Yes \| 市场价 \| AI% \|` 表行被正则抠出 `aiProb/marketProb`，喂进 `buildPlanForOutcome` 算 1/4 Kelly 真实下单。 | **高**。任何动到表格格式的风格改动，可能让正则抠到 0 → 静默不下单或下错单。 |
| **B. C 端研究控制台**（`/research`） | `api-driver.ts:80` 生成 → 仅 `splitNarration` 做逐行叙述展示 | **否（装饰性）**。展示用的数字来自 `buildPredictionDemoRun` 确定性脚手架，模型文字不被解析。 | **低**。这里是大胆做风格实验、上「润色 pass」的安全区。 |
| **C. 内部技术归档**（runtime-artifacts） | `reports/pulse/...` | 否 | 低。可保留 `Davidson`/`Elo`/`p_stat` 等术语，禁词不约束这里。 |

**含义**：风格控制要**按面分层**，不能一套规则全局套。A 面的硬约束是「保护正则契约」，B 面才是「追求 The Information 语感」的主战场。

> 顺带发现一个**自相矛盾**需一并修：声称「C 端禁用贝叶斯黑话」，但生成 prompt 自己就在注入「贝叶斯/Bayesian」——`api-driver.ts:86/94`（C 端!）、`full-pulse.ts:862/891/948`。加 house style 的同时必须改掉这几行,否则 prompt 自己打自己脸。

## 2. 两条校准红线（真钱产品，最危险的坑）

对抗评审认为，单纯照搬 The Information 那种「强观点、结论前置」的语气，对一个**预测产品**会朝错误方向用力。两个具体坑：

### 红线 ①：别让「结论前置」把不确定性挤出视野

- The Information 的法则是「第一句给最强结论」。但若首句只给点估计（`英格兰约 52% 胜率`），把区间（`46%–58%`）降级到后面，**只读第一句的人会把一个接近抛硬币的判断当成自信断言**——这是教科书式的「靠信息排序制造虚假自信」。
- **规则修正**：当概率区间**跨越决策边界**（接近 50% / 接近不操作线）或**带宽 > ±5pp** 时，**首句必须同时带区间**。
  - ✅ `英格兰约 52%（区间 46%–58%，接近平手）`
  - ❌ `英格兰约 52% 胜率`（区间被藏到后文）

### 红线 ②：few-shot 不能只朝「更自信」一个方向训练

- 5 个 bad→good 示例如果**全部**是「软词 → 干脆数字」（越改越自信），模型只会学到一条：hedge 是弱点，要换成爽快的数。**而预测产品的真正失效模式是过度自信，不是啰嗦。**
- **规则修正**：示例集必须包含**反向梯度**——至少 2 对是「bad = 过度自信 / 无概率断言」→「good = 补回校准的不确定性」。
  - bad `巴西必进四强，约 88%` → good `巴西四强约 72%（区间 64%–78%）；下行风险集中在伤病，若 X 则该判断失效`

### 附带红线：示例别教模型编数字

- 草案里的 good 示例凭空造了 `Elo 高出 112 分`、`统计基线 78.5%` 这类 bad 版没有、也没标来源的精确数字——这是在教模型「想过风格检查就编一个像样的数」。真钱产品上这是最危险的习惯。
- **规则**：示例里每个具体数字要么带 `（来源 + 日期）`，要么显式标注「示意」。

## 3. 风格机制评分（怎么控，按性价比）

| 机制 | 有效性 | 成本 | 可控性 | 结论 |
| --- | --- | --- | --- | --- |
| ① prompt 内联 house style 块 | 中 | 极低 | 中 | **首选**。把「只存在于记忆里的指令」变成真约束，零新增延迟。 |
| ②-lite 确定性正则闸门 | —（安全性） | 极低 | 高 | **P0/阻断级**。复用 `extractProbabilities` 正则跑一遍报告，抠到 0 行就**大声报错**，别让真钱链路静默失败。 |
| ③ few-shot 好坏对照 | 高 | 低 | 高 | **次选，要精简**。每面 1 对，重点放 C 端短输出。双语维护成本要控。 |
| ④ 离线 grep 风格 eval | 中 | 低 | 中 | **第三步**。对归档报告跑禁词/表格存在性检查，防模型/prompt 改版后风格悄悄退化。 |
| ⑤ 独立润色 pass（二次 LLM 改写） | 高 | 高 | 高 | **仅限 C 端**。绝不在 full-pulse 上跑（会动 trade-bearing 表行；live run 已 12–15 分钟）。 |
| ⑥ LLM-judge 重生成循环 | 高 | 极高 | 高 | **报告链路上否决**。非确定性 + 倍增延迟，压在真钱关键路径上不值得。仅作离线 eval（=④）。 |

**否决理由（核心）**：A 面（报告）已经是 12–15 分钟/轮、渲染占 95% 成本的真钱关键路径，任何同步且昂贵的机制（⑤⑥）都是过度工程；它真正需要的不是 LLM 裁判，而是一个**确定性正则闸门**——因为「约 42%」这种叙述会被抠成 0 而静默失败。

## 4. House Style（可粘贴块）

> 用法：作为 prompt 约束块注入。**A 面（full-pulse 报告）**用 §A+§通用；**B 面（C 端控制台）**用 §B+§通用。规则可逐条核查。

### §通用（所有面）

1. **首句法则**：第一句是整段最有信息量的判断，至少含一个硬信息（概率/数字/日期/专有名词）。禁止铺垫开场：`随着…`、`近年来`、`众所周知`、`值得注意的是`、`首先来看`。
2. **硬信息法则**：每句至少一个具体物（数字/百分比/日期/人名/队名/机构）。没有硬信息的句子并进有的，或删。**例外**：每个 section **允许且仅允许一句**不带硬信息的因果/判断旁白（这正是 Levine/Stratechery 的味道，全禁会退化成行情终端 feed）。
3. **具体替代形容词**：`实力强劲`→那个支撑它的数（`Elo 高 112 分`）。**形容词出现 = 你没拿到那个数字。**
4. **数字带基准**：任何单独数字配一个比较系（对上期/对手/目标/占比）。`Elo 1991`→`Elo 1991（世界第 5）`。
5. **不确定性 = 带界限的数字**：用区间/`至少`/`最多`/`约`，不用软模态词堆叠（`可能或许大概`）。**概率永远是数字，不是气势。**
6. **来源即不确定性**：每条非公开事实标来源类型 + 日期（`FIFA 官方名单 2026-06-02` / `两位看过文件的人士`）。禁裸 `据报道`/`有消息称`。**禁止为凑风格编造无来源数字。**
7. **动词与句法**：用及物具体动词（领跑、压到、退出、补招、连胜）。禁姿态动词（`有望`、`致力于`、`旨在`、`蓄势待发`、`赋能`）。一句一事实；删连接词脚手架（`此外`、`再者`、`总而言之`）。
8. **节奏变化**（别变电报体）：**不要**机械地每句等长一事实——那本身是另一种机器腔。密句之后允许并鼓励一记短句收力。
9. **不复述、向前收尾**：段落不得以复述结尾；落在最新/最前瞻的具体事实或后果（kill condition、下一个待验证节点）。禁 `综上所述`、`由此可见`。
10. **禁 ChatGPT 腔（可 grep 的黑名单）**：三段式排比（rule-of-three）、`不是 X，而是 Y` 滥用、对称排比、`让我们/首先/接下来` 脚手架、空心总结动词。

### §A（full-pulse 报告 — trade-bearing，硬约束）

- A1. **概率表是程序契约，不是排版**。每个市场 section 必须含一张表，**严格匹配** `pulse-entry-planner.ts:230` 的正则：
  - 半角竖线 `|`、半角数字、百分号 `%` 结尾、行标签是 `Yes`/`No`。
  - 形如 `| Yes | 52.0% | 58.0% |`（市场价 / AI 估算两列）。
  - **禁止**：`52 percent`、全角 `％`、`Yes 概率 52%` 这种纯文字描述——会被抠成 0 → 静默不下单。
- A2. 市场价列**必须保留**（trade-bearing 报告靠它算 edge）。— 注意这与 B 面的市场盲测相反，见 §合规。
- A3. 表必须出现在每个 section 的前部（结论区），不要埋在文末。

### §B（C 端研究控制台 — 决策优先、零黑话）

- B1. 先给判决 + 概率，证据作为来源卡片在后。
- B2. **禁用黑话词（用户可见文案一律不出现）**：`节点`、`贝叶斯`、`贝叶斯更新`、`置信区间`、`可信区间`、`条件概率模型`、`edge`、`先验`、`后验`、`似然`、`蒙特卡洛`。
  - 平替：`贝叶斯更新`→`结合证据更新判断`；`置信区间/可信区间`→`概率区间`/`把握范围`；`条件概率模型`→`分步拆解`；`节点`→`环节`；`edge`→`扣费后预期收益`/`净优势`。

### §合规（按面分层，别全局套）

- **市场盲测**只对**公开预测产品（如世界杯 C 端）**生效：禁止读取/引用/展示任何盘口、赔率、市场隐含概率。
- **但 A 面 full-pulse 交易报告必须保留市场价列**（正则要解析它）。所以「市场盲测」是 B 面红线、不是 A 面红线——评审 rubric 的盲测否决项必须**按面生效**，否则会把每一份合法交易报告判失败。
- 正式报告保留免责声明（概率非确定性、过往不代表未来、合规提示）。

### 写前自检

- [ ] 首句最强判断 + 硬信息，无铺垫；概率近边界时区间同句出现
- [ ] 每句一锚点（除每段≤1 句旁白）；数字带基准；形容词没替代数据
- [ ] 不确定性是区间/限定数字；强观点配 kill condition；未编造无来源数字
- [ ] 无姿态动词、无连接词脚手架、无 ChatGPT 腔（三段式/不是X而是Y）
- [ ] 节奏有长短变化，不是电报体；结尾向前一步不复述
- [ ] A 面：概率表严格匹配正则，市场价列在；B 面：零黑话，市场盲测

## 5. 评审 Rubric（LLM-judge / 离线 eval）

每维 0–3，满分 21。通过线**按面分别校准**（别用一个 16/21 拍脑袋数；先拿 `runtime-artifacts/reports/pulse/` 里 ~20 篇真实报告人工打分定线）。**拆成「确定性子检查（0/1 机器跑）+ LLM 语感分」两层**，别把 vibe 判断伪装成阈值。

**确定性子检查（机器跑，命中即客观）**：
- 禁词 grep（B 面：节点/贝叶斯/置信区间/edge…）
- 概率表正则存在性（复用 `extractProbabilities`，A 面抠到 0 = 直接失败）
- 形容词密度计数、hedge 计数、连接词脚手架计数
- 三段式/`不是X而是Y` 模式匹配

**LLM 语感维度（0–3 各）**：首句强度 / 每句信息增益 / 具体性(数字带基准) / **Hedge 纪律（软词↔过度自信两头都扣分）** / 不复述 / 动词句法 / 声音合规。

**硬否决（命中任一直接不通过）**：
- B 面/公开产品引用任何市场价格/赔率/隐含概率（盲测红线，**仅 B 面**）
- B 面出现禁用黑话词
- 绝对化预测（`必胜`/`一定`/`稳了`）无概率，或概率无来源
- A 面概率表无法被正则解析
- 正式报告缺免责声明

> Hedge 维度要双向：`软模态词较多`扣分，`梭哈式无概率绝对断言`同样扣分——这是把红线②写进打分。
